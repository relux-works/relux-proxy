# Privacy-safe diagnostics, disclosure, and support export

## Description
Give users useful runtime and support information without exposing credentials, traffic, destinations, DNS queries, or full local addresses. Disclose the baseline VPN data flow and zero-telemetry posture before enablement and provide an inspectable, redacted, user-initiated export.

## Scope
In scope: bounded runtime events and aggregate metrics, versioned diagnostic snapshots, approved and prohibited fields, redaction, retention and deletion behavior, diagnostics summary UI, support-export category preview, manifest, platform share/save handoff, pre-VPN privacy disclosure, settings disclosure, zero analytics and traffic telemetry verification, exit-host and system-exclusion explanations, accessibility, unit/security/UI tests, and physical acceptance. Out of scope: packet payload capture, DNS or destination logging, raw addresses, crash-report vendor integration, opt-out analytics for baseline, future telemetry, public privacy-policy hosting, legal licensing decisions, and release submission.

## Acceptance Criteria
1. Default diagnostics are bounded and limited to approved timestamps, states, lane identifiers, aggregate counts, error domains/codes, memory observations, negotiated algorithms, relay identity, and redacted address-family facts. 2. Automated adversarial tests prove keys, passphrases, packet payloads, DNS names, destination hosts or IPs, full local addresses, shell input, and traffic samples cannot enter logs, snapshots, crash annotations, or support exports. 3. A user can inspect diagnostic categories, preview the exact export manifest, create an export only on explicit action, and delete retained local support data on iOS and macOS. 4. Before first VPN enablement the app explains processed data, the user-controlled SSH exit, exit-host visibility, Relux Works absence from the baseline data path, system-excluded traffic, retention/deletion, and zero traffic telemetry. 5. Extension-to-app diagnostic transfer is versioned, size-bounded, stale-generation safe, and remains useful after containing-app relaunch. 6. Unit, property/fuzz where appropriate, UI, and physical acceptance tests verify redaction, bounds, disclosure gating, export preview/output, deletion, accessibility, and no analytics or traffic-telemetry endpoints.
