# Onboarding, accessibility, localization, and legacy migration

## Description
Guide a new user from product understanding and SSH prerequisites through profile creation, host trust, privacy acknowledgement, system VPN permission, first connection, recovery, and support on iOS and macOS. Establish release-grade accessibility and an explicit migration boundary from the current macOS SOCKS product.

## Scope
In scope: first-run and resumable onboarding, SSH host prerequisite guidance, privacy acknowledgement before VPN enablement, profile/trust/permission handoffs, empty and recoverable error states, settings/help entry points, VoiceOver and macOS accessibility, keyboard navigation, focus order, Dynamic Type and text scaling, contrast, reduced motion, localization-ready copy, pseudo-localization, shared accessibility identifiers, current SOCKS coexistence/replacement/retirement decision, approved defaults/history migration, iOS/macOS UI tests, and physical end-to-end acceptance. Out of scope: implementing a public SOCKS server, OpenSSH config import, ProxyJump, release notarization, TestFlight upload, App Store submission, regional licensing decisions, and unsupported locale translations.

## Acceptance Criteria
1. A first-time user on iOS and macOS can understand the self-hosted SSH model, complete or resume prerequisites, create a profile, trust a host, acknowledge privacy terms, grant VPN permission, connect, understand capability or failure, obtain help, and disconnect. 2. Privacy disclosure appears before the first enable action and onboarding does not claim anonymity, a Relux exit network, or capabilities not present in the selected mode. 3. All M4 surfaces have stable shared accessibility identifiers, meaningful labels/hints/values, logical focus, keyboard operation on macOS, VoiceOver operation, supported text scaling, sufficient contrast, and reduced-motion behavior. 4. User-facing strings are externalized, pseudo-localization and text expansion pass, and the approved launch-locale policy and fallback are documented. 5. A reviewed decision selects legacy SOCKS coexistence, replacement, or retirement and defines handling of host/account/port defaults, existing release history, bundle/storage identity, rollback, and user messaging before migration code runs. 6. Automated UI journeys plus named physical iPhone and Apple-silicon Mac acceptance cover first run, relaunch/resume, permission denial, empty/error recovery, migration path, full/degraded/failure states, diagnostics, accessibility, and screenshot review.
