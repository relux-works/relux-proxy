# Path-aware reconnect and route-safe reasserting state machine

## Description
Implement a generation-safe reconnect controller that reacts to physical-path, SSH, relay, viability, and lifecycle events, reconnects through the selected physical interface, rebuilds the exact endpoint exclusion and tunnel settings, restores safe DNS and capabilities in order, and keeps ordinary traffic scoped to the VPN while reasserting.

## Scope
In scope: explicit disconnected, connecting, connected-full, connected-degraded, reasserting, failed, and disconnecting states; NWPath and viability inputs; cached endpoint attempts; required-interface resolution and connect; actual IPv4, IPv6, or synthesized endpoint capture; verified host identity continuity; bounded jittered retry; terminal authentication and host-key behavior; generation and stale-callback rejection; old/new transport memory reservation; exact host-route exclusion replacement; atomic network settings; mandatory control lane, packet plane, TCP, safe DNS, relay, and optional-lane restoration order; provider reasserting and capability snapshots; cancellation, diagnostics, deterministic faults, and physical path-change evidence. Out of scope: silently accepting host changes, broad subnet exclusions, physical DNS fallback, preserving UDP associations across transport generations, final NAT64, sleep, or captive matrices owned by STORY-260715-3ao1u9, final route-mode implementation owned by STORY-260715-21c23x, or UI presentation.

## Acceptance Criteria
1. A complete transition table defines every state, event, readiness predicate, cleanup action, retry class, capability, and published reason and rejects illegal or stale transitions. 2. Reconnect first tries verified cached endpoint IPs and uses an NWConnection constrained to the selected physical interface for fresh resolution or connect when required, then records the actual remote endpoint. 3. Host-key mismatch, authentication rejection, and invalid configuration are terminal until user or configuration change, while transient path errors use bounded jittered retry that resets only after stable service. 4. The exact endpoint exclusion and network settings are replaced for the current generation before packet reads and capability publication, with no recursive route loop or broad bypass. 5. Mandatory lane A, safe DNS, packet and TCP paths, relay capability, and optional lanes restore in the documented order, and reasserting clears only when the advertised full or degraded mode is usable. 6. User stop promptly cancels paths, timers, attempts, settings work, lanes, tasks, and descriptors, and reconnect overlap obeys the memory reservation. 7. Fault tests and physical Wi-Fi to cellular, cellular to Wi-Fi, loss, and server-address-change trials prove zero ordinary DNS or traffic fallback, bounded outage and retries, generation safety, and resource return to baseline.
