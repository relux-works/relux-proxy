# Explicit QUIC behavior and compatible or fail-closed route modes

## Description
Implement fast, observable destination UDP/443 policy for Auto, Allow QUIC, and Block UDP/443, plus compatible and platform-scoped fail-closed tunnel route modes that preserve exact SSH endpoint exclusions, safe DNS, accurate Apple exception semantics, and loop-free lifecycle behavior.

## Scope
In scope: destination UDP/443 classification; explicit local unreachable or equivalent bounded failure; Auto decisions from current SSH lane loss and latency evidence; Allow forwarding through validated relay capability; policy generation and counters; unrelated UDP and DNS separation; compatible dual-stack routes; includeAllNetworks where supported; platform capability checks and documented system exceptions; exact endpoint host routes; startup, reconnect, rollback, and mode-change integration; privacy-safe diagnostics; deterministic policy and route faults; physical capture matrix. Out of scope: payload inspection, per-app routing, silent timeout-based blocking, blocking Apple traffic outside platform guarantees, absolute kill-switch claims, changing relay protocol, physical DNS fallback, fake DNS, final UX copy, or product telemetry.

## Acceptance Criteria
1. Allow QUIC forwards eligible UDP/443 only through a current validated relay generation, Block UDP/443 returns the documented fast local failure, and neither mode silently times out or affects unrelated UDP or tunnel DNS. 2. Auto uses versioned lane-health inputs, deterministic thresholds and hysteresis, rejects new UDP/443 quickly when QUIC-over-SSH is predicted to underperform, and records only aggregate reasons. 3. Full, degraded, reasserting, failed, stopping, and stale-generation states each have one explicit UDP/443 outcome with no physical socket fallback. 4. Compatible mode installs dual-stack defaults and only approved exact exclusions, while fail-closed mode enables includeAllNetworks only where supported and exposes the documented system exceptions without absolute claims. 5. Startup, live mode change, endpoint replacement, reconnect, settings failure, and stop apply or roll back route and DNS settings without a recursive route, broad exclusion, false-connected snapshot, or ordinary DNS leak. 6. Unit, fault, and golden tests cover policy decisions, fast-failure latency, unrelated traffic, platform branches, exact routes, rollback, and redaction. 7. Physical iPhone and Mac captures across compatible and fail-closed modes and full, degraded, and reasserting capabilities match the disclosed traffic matrix and record OS behavior changes.
