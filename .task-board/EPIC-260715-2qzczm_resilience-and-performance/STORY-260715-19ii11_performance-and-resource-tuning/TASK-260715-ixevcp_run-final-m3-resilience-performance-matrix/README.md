# Run and publish the final M3 resilience and performance acceptance matrix

## Description
Execute the final locked-configuration named-device matrix across packet, lane, rekey, memory, reconnect, NAT64, sleep and wake, captive, QUIC, compatible and fail-closed routes, performance, energy, leaks, and repeated cleanup, then publish accepted baselines and explicit red follow-ups.

## Scope
In scope: final pinned source and dependencies; accepted or provisional parameter set; named iPhone and Mac; required MTUs, families, lanes, windows, rekey, traffic, concurrency, loss and latency, memory pressure, path changes, NAT64, sleep and wake, captive, app termination, relay full and degraded, QUIC policies, route modes, DNS and route captures, CPU, energy, throughput, TTFB, DNS latency, packet and syscall rate, footprint, peak, queues, drops, errors, descriptors, and cleanup; evidence manifest; regression thresholds. Out of scope: changing parameters during acceptance, hiding red rows, release marketing claims, unsupported-device extrapolation, public-user traffic, or declaring acceptance before blockers are resolved.

## Acceptance Criteria
1. A TASK-ID-scoped matrix records every protocol field, final configuration, raw artifact reference, automated and physical result, pass, red, or unavailable status, owner, and reproduction command for all required rows. 2. Byte and protocol integrity pass, nominal runs have no ordinary loss, induced pressure remains bounded, routes have no loop or broad bypass, and ordinary DNS or application traffic never falls back outside disclosed platform exceptions. 3. Lane policies meet recorded control and throughput baselines, rekeys survive mixed multi-gigabyte traffic, and memory footprint, peak, queues, windows, sessions, associations, overlap, and pressure actions remain within accepted ceilings without avoidable jetsam. 4. Path, endpoint, NAT64, sleep or wake, captive, relay loss, QUIC, and both route modes publish truthful states, fail promptly where required, restore current generations, and clean resources across repeated cycles. 5. The publication names accepted device and OS baselines, parameter values, statistical thresholds, energy and performance regressions, red or unavailable rows, conditional HEV disposition, follow-up task IDs, and privacy-safe raw evidence locations.
