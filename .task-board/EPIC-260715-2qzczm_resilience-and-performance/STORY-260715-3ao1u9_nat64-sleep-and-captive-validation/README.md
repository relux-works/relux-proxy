# NAT64, sleep-wake, captive-network, and lifecycle hardening

## Description
Harden and validate the M3 runtime across IPv6-only NAT64, address-family changes, sleep and wake, captive-network transitions, containing-app termination, provider stops, and repeated lifecycle loops on named physical iPhone and Mac configurations.

## Scope
In scope: NAT64 synthesized endpoint capture and exclusion replacement; IPv4, IPv6, dual-stack, and IPv6-only transitions; sleep and wake event coalescing; path and reconnect ownership; captive negotiation within Apple system exceptions; compatible and fail-closed behavior; safe DNS continuity or explicit failure; UI process termination independence; cancellation during start; provider stop reasons; repeated start and stop; stale-event rejection; deterministic simulation; authorized physical captures; device, OS, revision, configuration, memory, route, counter, and cleanup evidence; support-matrix regression triggers. Out of scope: private Network Extension APIs, promising captive traffic is tunnelable when Apple excludes it, physical DNS fallback, automatic host-key replacement, final marketing claims, unsupported hardware, or tuning without the performance story evidence process.

## Acceptance Criteria
1. A versioned device, OS, interface, address-family, route-mode, event, traffic, and capture matrix names every required row, fixture, metric, expected outcome, and evidence location before physical execution. 2. IPv6-only and NAT64 starts and transitions use the actual connected endpoint and an exact current-generation exclusion, preserve IPv4 and IPv6 application behavior where supported, and never deadlock in stale routes. 3. Sleep and wake produce at most one current reconnect sequence, cancel stale work, restore only truthful capability, and keep reconnect overlap within the memory ceiling. 4. Captive-network handling matches compatible and fail-closed disclosures and Apple exceptions while ordinary traffic and DNS remain tunneled or fail explicitly. 5. Containing-app termination does not tear down a healthy provider, while cancellation, provider stop, and repeated lifecycle loops release routes, tasks, timers, channels, associations, sockets, and descriptors. 6. Deterministic fault tests cover synthesized-address changes, sleep races, captive transitions, UI termination, stop during start, late callbacks, and API capability changes. 7. Physical iPhone and Mac evidence records every supported row, identifies red or unavailable rows without waiver, and publishes regression triggers when OS behavior differs.
