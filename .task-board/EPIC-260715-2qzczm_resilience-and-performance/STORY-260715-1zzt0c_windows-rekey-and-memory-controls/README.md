# Channel windows, rekey, and extension memory controls

## Description
Implement per-channel receive-window policy, automatic client and server rekey handling, a cross-layer extension memory ledger, ordered memory-pressure actions, and a hard reconnect-overlap reservation so permitted buffering and replacement transports cannot cause unbounded growth or avoidable jetsam.

## Scope
In scope: control, ordinary, bulk, and relay window profiles; capped bandwidth-delay-product calculation; window-credit accounting; WINDOW_ADJUST withholding; byte and elapsed-time rekey; server-initiated rekey; key-exchange admission pauses; lane-local rekey failure; advisory os_proc_available_memory sampling; soft, pressure, and critical watermarks; HEV sessions and caches, socket buffers, DNS cache, relay buffers, channels, lane count, queued bytes, and reconnect overlap in one ledger; fast refusal and controlled failure; privacy-safe metrics; fault, allocation-bound, soak, and physical-memory tests. Out of scope: selecting the SSH engine, claiming advertised credit is eagerly allocated, relying on jetsam as control flow, changing relay framing, final performance constants before measurement, live flow migration, or application UI.

## Acceptance Criteria
1. Initial windows are configurable per channel class, use 32 KiB and 64 KiB candidates plus a capped bulk BDP calculation, and cannot multiply an uncapped default by maximum sessions. 2. Window adjustment is bounded by the current ledger and is withheld under pressure without attempting to revoke prior credit. 3. Client byte and time thresholds and server requests survive active direct-tcpip and relay traffic, while new-channel assignment pauses safely during key exchange. 4. Rekey failure isolates the affected lane first, emits a finite reason, and cannot leak, duplicate, or migrate existing byte streams. 5. The memory controller measures all declared consumers, treats available memory as uncached advisory input, and applies the specified soft, pressure, and critical actions in order. 6. Old and replacement transports cannot coexist beyond an explicit reservation, and critical pressure releases the old transport before replacement or stops explicitly. 7. Fault and allocation tests plus a physical at-least-5-GiB mixed soak record footprint, peak, available memory, sessions, windows, queues, channels, drops, rekeys, descriptors, and cleanup with no unbounded growth or avoidable jetsam.
