# Explicit capability negotiation and leak-safe degraded mode

## Description
Expose truthful full, degraded, and failed tunnel capabilities and preserve useful TCP plus tunnel-owned safe DNS when the relay cannot be installed, negotiated, or kept alive. Reject unsupported UDP explicitly, prevent ordinary DNS fallback, and restore full mode only after a clean relay handshake.

## Scope
In scope: capability bit and reason taxonomy; full, degraded, failed, and reasserting-compatible state contract; relay build and limit evidence; versioned provider snapshots; bootstrap, handshake, process, and lane failure mapping; association invalidation; deterministic degraded safe-DNS policy using the existing SSH DNS-over-TCP path or an explicitly approved tunneled DoH alternative; TCP continuity; explicit UDP and QUIC-family rejection policy input; fail-safe DNS behavior; bounded reprobe and full-mode restoration; diagnostics, user and operator documentation; state, fault, leak, harness, and physical transition tests. Out of scope: implementing TCP direct forwarding, M3 multi-lane scheduling, general path-change reconnect, includeAllNetworks fail-closed mode, captive or NAT64 transitions, final UI visuals, analytics, and silent physical fallback.

## Acceptance Criteria
1. A versioned capability model distinguishes usable full mode, usable degraded TCP plus safe DNS, mandatory failure, and reasserting-compatible transitions with stable privacy-safe reason codes. 2. Unsupported platform, absent asset, bootstrap failure, checksum or version mismatch, relay exit, framing failure, and relay-lane loss invalidate UDP associations and enter degraded mode only when TCP and the selected safe-DNS path are actually usable. 3. In degraded mode TCP remains usable, DNS uses only the approved tunneled fallback, ordinary UDP is rejected explicitly, and controlled access-side monitoring observes zero ordinary DNS or application UDP fallback to the physical interface. 4. Full mode is advertised again only after a fresh validated relay handshake and limits exchange; stale callbacks or sessions cannot resurrect capability. 5. Automated and physical transition evidence covers startup degraded, full-to-degraded, degraded-to-full, safe-DNS failure, stop, repeated reprobe, bounded memory, truthful snapshots, redacted diagnostics, and user-facing limitations.
