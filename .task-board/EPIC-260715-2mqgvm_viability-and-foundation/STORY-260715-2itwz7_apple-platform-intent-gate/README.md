# Gate A0 — Apple packet-tunnel intended-use viability

## Description
Establish authoritative, reviewable evidence that the disclosed Relux data plane qualifies for the intended Network Extension packet-tunnel entitlement and App Store distribution, or record an architecture pivot before any production implementation is accepted. The disclosure must state that HEV terminates device TCP locally and that user payload then travels only inside authenticated SSH connections to a user-selected remote exit host.

## Scope
In scope: point-in-time primary Apple guidance; an exact architecture and data-flow disclosure; selection and execution of an accepted evidence route through Apple Developer Technical Support, entitlement feedback, accurately disclosed prototype review, or a packet-semantic remote-endpoint pivot; preservation of submissions, responses, constraints, and a Gate A0 decision. Out of scope: production tunnel code, claims of approval inferred only from local installation, marketing language, and regional legal analysis beyond recording a required follow-up.

## Acceptance Criteria
1. A dated evidence dossier cites the controlling Apple sources and describes the complete packet, TCP, SSH, DNS, and exit-host behavior without euphemism. 2. The dossier identifies the TN3120 ambiguity and asks a decision-capable Apple channel a concrete intended-use and distribution question. 3. Gate evidence is one of the accepted forms: written DTS response, entitlement or review feedback for an accurately disclosed prototype, or an approved architecture change that carries packet semantics to a remote VPN endpoint. 4. Reproducible artifacts record submission text, dates, case or review identifiers, responses, redactions, and source revision. 5. A decision record declares pass, fail, or pivot, states constraints and affected downstream work, and leaves production tasks blocked on any negative or ambiguous result.
