# M0 packetFlow, socket-pair, and HEV bridge spike

## Description
Prove on macOS and a physical iPhone that public Network Extension packetFlow APIs can exchange bounded datagrams with unmodified upstream HEV and bundled lwIP through a nonblocking AF_UNIX SOCK_DGRAM socket pair, with correct Darwin family framing, backpressure, cleanup, instrumentation, MTU behavior, and an extension memory baseline.

## Scope
In scope: pinned upstream HEV, core, task-system, and lwIP revisions and notices; Swift PacketFlowBridge; Darwin four-byte family headers; nonblocking socket buffers and effective-limit inspection; bounded batching and time budgets; reason-specific drops and fatal-error semantics; fixed HEV UDP-in-TCP mode; process-local SOCKS boundary; IPv4 and IPv6 traffic; MTU 1500, 4096, and 8500; socket pressure; repeated lifecycle and concurrency tests; physical footprint and available-memory evidence; fork-versus-upstream decision. Out of scope: private utun discovery, file-descriptor scanning, SSH transport, remote UDP relay, production route or DNS policy, lane scheduling, full application UX, and performance claims not backed by before-and-after measurements.

## Acceptance Criteria
1. The spike uses only NEPacketTunnelFlow and documented Darwin socket APIs and contains no utun control access, descriptor discovery, or private API. 2. Forward and reverse paths preserve packet boundaries, add or validate and strip network-byte-order AF_INET or AF_INET6 headers, batch writes, and count malformed or unsupported frames. 3. EAGAIN, EWOULDBLOCK, and ENOBUFS cause bounded reason-specific drops; EMSGSIZE fails start with attempted and effective limits; persistent errors and cancellation release all tasks and descriptors. 4. Upstream HEV runs with socks5.udp set to tcp and the stated low-memory baseline, and its internal SOCKS endpoint rejects unowned ingress. 5. Swift Testing and fault-injection coverage verifies framing, batching budgets, saturation, MTU errors, cleanup, repeated start and stop, IPv4, and IPv6. 6. Physical iPhone and macOS evidence covers MTUs 1500, 4096, and 8500; constrained buffers; receiver stalls; nominal mixed traffic; staged concurrency; and lifecycle loops with device, OS, revisions, traffic shape, counters, descriptors, CPU, syscall rate, physical footprint, peak, and available-memory samples. 7. A gate report selects measured MTU, buffer, batch, and session baselines, states whether the 25–30 MiB target is met, and permits a HEV fork only when Instruments evidence shows a material bottleneck and a measured callback improvement.
